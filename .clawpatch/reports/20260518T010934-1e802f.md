## low: Malformed outlier timestamps can crash price verification

id: fnd_sig-feat-library-08079f3e07-5dad_10cd299817
category: bug
confidence: high
triage: confirmed-bug
status: open
feature: Python source pipeline (feat_library_08079f3e07)

evidence:
- pipeline/extractor.py:281-286 (_verify_lot)
- pipeline/extractor.py:363-369 (_parse_hhmmss)
- tests/test_extractor.py:548-561 (TestVerifyLot)

_verify_lot treats missing or out-of-window timestamps as unverifiable, but a present malformed timestamp is passed directly to _parse_hhmmss, which raises ValueError. Because LLM-generated timestamp_start is only a plain string on Lot, an outlier with a value like '5:00' or '00:05:00.000' can abort the whole extraction instead of returning None and letting the caller discard only that price.

recommendation:
Catch ValueError/TypeError around _parse_hhmmss inside _verify_lot and return None, or normalize/validate timestamp_start before verification.

test analysis:
The tests cover missing timestamps and timestamps outside all windows, but they do not cover a malformed non-empty timestamp reaching _verify_lot.

suggested regression test:
Add a _verify_lot test with timestamp_start='5:00' or 'not a timestamp' and assert it returns None without calling the client.

minimum fix scope:
pipeline/extractor.py _verify_lot plus one test in tests/test_extractor.py.

## medium: LLM failures are cached as successful extraction results

id: fnd_sig-feat-library-08079f3e07-cf29_d7684f94db
category: data-loss
confidence: high
triage: confirmed-bug
status: open
feature: Python source pipeline (feat_library_08079f3e07)

evidence:
- pipeline/extractor.py:107-109 (extract_lots)
- pipeline/extractor.py:127-132 (extract_lots)
- pipeline/extractor.py:261-263 (extract_lots)
- pipeline/extractor.py:591-604 (extract_metadata)

If an LLM call fails for one lot window, extract_lots logs a warning, continues, then writes lots_<id>.json. A later run treats that partial file as a valid cache and skips extraction entirely. Metadata has the same pattern: any extraction error becomes cached empty metadata. This can silently produce incomplete auction results that resume will not repair without manual cache invalidation.

recommendation:
Track whether any extraction or metadata call failed and do not write the normal checkpoint unless the stage completed successfully. Either raise so batch mode records a failed item, or write an explicit incomplete/error artifact that resume does not treat as success.

test analysis:
tests/test_extractor.py exercises parsing, merge, verification, and a happy-path extract_lots burst case, but it does not simulate a client.complete exception during a multi-window extraction or assert cache behavior after failure.

suggested regression test:
Add an extract_lots test with two windows and a mock client that raises on one window; assert the normal output_path is not written and the caller sees a failure or explicit incomplete status. Add a metadata test that a client failure does not write cached {} as a successful metadata file.

minimum fix scope:
pipeline/extractor.py extract_lots and extract_metadata failure paths, plus focused tests in tests/test_extractor.py.

## medium: Price coercion silently turns invalid values into persisted prices

id: fnd_sig-feat-library-88af11a688-f8f4_8195c49e21
category: bug
confidence: high
triage: confirmed-bug
status: open
feature: Python source models (feat_library_88af11a688)

evidence:
- models/lot.py:31-34 (coerce_price_value)
- models/lot.py:58-61 (Lot.coerce_price)

The price validator accepts anything float() can parse and returns it without rejecting booleans, negative values, or non-finite numbers. Because bool is numeric in Python, unit_price=True becomes 1000.0 after the under-100 repair; strings like "-3.100,00" become -3100.0; "NaN" and "Infinity" survive as floats. These are not valid auction prices and can be written into the durable model/output instead of being rejected or nulled.

recommendation:
After parsing, reject bool before numeric conversion and require the parsed float to be finite and non-negative. Choose the existing pipeline policy explicitly: either raise a validation error for invalid price inputs, or return None so later windows can recover the value.

test analysis:
The feature metadata lists no linked tests. Existing lot model tests cover valid Brazilian formats, empty strings, zero, and the under-100 repair, but not bool, negative, NaN, or Infinity price inputs.

suggested regression test:
Add tests in tests/test_lot_model.py asserting unit_price and total_price reject or null True/False, negative numeric/string values, NaN, and Infinity.

minimum fix scope:
models/lot.py price coercion plus focused Lot model tests for invalid price inputs.

repro:
Lot(lot_number=1, sex="macho", category="bezerro", num_animals=5, breed="Nelore", unit_price=True).unit_price returns 1000.0; unit_price="-3.100,00" returns -3100.0; unit_price="NaN" returns nan.
